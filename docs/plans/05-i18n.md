# 5. Languages (i18n)

Comes first: every other plan adds interface text, and should write it through this from the start.

## Decisions

- **English and Portuguese (Brazil)** in v1: the whole interface, messages, the page templates and their hints.
- **The browser's language** until the learner picks one; the choice is saved **on the account** (it follows them to any device) and changed from the account menu.
- Changing the language changes the interface and what is inserted from then on (templates); what is already written in pages stays as it is.
- The NestJS sample path stays in English for everyone.

## How it works

- **Messages** live in `apps/web/i18n/messages/en.ts` (the source, with the keys) and `pt-BR.ts`, typed so a missing or extra key in Portuguese is a compile error. Values are strings with `{name}` placeholders, or `{ one, other }` for plurals (resolved with `Intl.PluralRules`).
- **`useT()`** returns `t(key, values)`; `useLocale()` the current language. Dates and times go through `Intl` with the same language (relative times with `Intl.RelativeTimeFormat`).
- **Which language:** the account's choice, else a `wp-locale` cookie, else the browser's `Accept-Language`, else English. The root layout reads the cookie and the header on the server, so the first render is already in the right language (no flash). Choosing a language saves it on the account and in the cookie.
- **Account:** `users.locale` (nullable: null follows the browser), `PATCH /api/auth/me { locale }`, `locale` in `GET /api/auth/me`.
- **Account menu:** "Language: English / Português (Brasil) / Same as the browser".
- **Domain error messages** are mapped to keys in the web (`useCases/messages.ts`), not translated in the domain.
- `<html lang>` follows the language.

## Checks

- Unit: the formatter (placeholders, plurals, a missing key falls back to English and is reported in development).
- Typecheck: `pt-BR` has exactly `en`'s keys.
- API: saving and reading the locale.
- Browser: a Portuguese browser sees Portuguese on first load; switching from the account menu changes everything at once and survives a reload and another browser; no English left on the main screens (a check that scans them for the English messages).
